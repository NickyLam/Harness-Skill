# 增量进度追踪模板

> Orchestrator 的进度记录资产

## 使用方式

每个增量完成后，在 `.harness/progress/` 下创建进度文件：

```
.harness/progress/
├── current.md          ← 当前进行中的增量
└── YYYY-MM-DD.md       ← 已完成的增量（按日期归档）
```

## 当前增量格式（current.md）

```markdown
# 当前增量进度

**功能**：<功能名>
**开始时间**：YYYY-MM-DD HH:MM
**当前阶段**：/spec / /plan / /build / /test / /review / /simplify / /ship
**当前角色**：PO / Architect / Implementer / Tester / Reviewer / Shipper

## 已完成

| # | 增量 | 阶段 | 状态 | 产出 | 完成时间 |
|---|------|------|------|------|---------|
| 1 | <描述> | /spec | ✅ | spec 文档 | HH:MM |
| 2 | <描述> | /plan | ✅ | 计划文件 | HH:MM |

## 进行中

| # | 增量 | 阶段 | 状态 | 阻塞原因 |
|---|------|------|------|---------|
| 3 | <描述> | /build | 🔄 | 等待测试通过 |

## 待开始

| # | 增量 | 阶段 | 依赖 |
|---|------|------|------|
| 4 | <描述> | /test | #3 |
| 5 | <描述> | /review | #4 |
| 6 | <描述> | /ship | #5 |

## 已知问题

1. <问题描述> → <解决方案/状态>

## 上下文摘要（用于角色交接）

```
<1-2段当前状态摘要，供新角色快速理解上下文>
```
```

## 增量完成归档格式（YYYY-MM-DD.md）

```markdown
# 增量完成记录 — YYYY-MM-DD

## 增量列表

| # | 功能 | 阶段 | 产出 | 耗时 |
|---|------|------|------|------|
| 1 | <功能A> | /spec → /ship | <产出> | X分钟 |

## 关键决策

1. <决策> → <原因>

## 踩坑记录

1. <问题> → <解决方案>

## 经验沉淀

- <提炼的规则>
```

## 增量回滚标记

如果当前增量失败需要回滚：

```markdown
## ⚠️ 回滚记录

**增量**：#X <描述>
**回滚时间**：YYYY-MM-DD HH:MM
**回滚原因**：<为什么失败>
**回滚范围**：<回滚了哪些文件>
**恢复方式**：<如何恢复到回滚前状态>
**经验教训**：<下次如何避免>
```
