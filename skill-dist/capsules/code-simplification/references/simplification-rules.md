# 代码简化规则

> code-simplification Skill 的 references/ 目录文件

## Chesterton 栅栏原则

> 在拆除栅栏之前，先了解为什么它被建起来。

不要删除你不理解的代码。每行代码都有添加它的理由：
- 可能是为了处理边界情况
- 可能是为了向后兼容
- 可能是某个 Bug 的修复
- 可能是性能优化

**行动**：删除前先调查，确认安全后再简化。

## 500 规则

- 任何函数不超过 **50 行**（理想 ≤20 行）
- 任何文件不超过 **500 行**
- 任何函数参数不超过 **5 个**
- 嵌套深度不超过 **3 层**

## 简化 Checklist

### 🔴 严重（必须简化）

- [ ] 函数超过 50 行
- [ ] 文件超过 500 行
- [ ] 死代码（未引用的函数/变量/导入）
- [ ] 嵌套超过 3 层
- [ ] 重复的业务逻辑（DRY 原则）

### 🟡 中等（建议简化）

- [ ] 只有 1 个实现的接口
- [ ] 只有 1 个调用的辅助函数
- [ ] 重复的 JSX 结构 → 提取组件
- [ ] 重复的条件判断 → 提取函数
- [ ] 过度泛化的参数类型

### 🟢 低（可选简化）

- [ ] 魔法值 → 提取常量
- [ ] 未使用的导入
- [ ] 可选链/空值合并的简化
- [ ] console.log 调试语句
- [ ] 过长的变量名 → 简洁命名

## 简化后验证

每项简化必须通过以下验证：
1. ✅ 测试全部通过（`npm run test`）
2. ✅ TypeScript 编译无错误
3. ✅ ESLint 检查通过
4. ✅ 行为不变（没有功能回归）
