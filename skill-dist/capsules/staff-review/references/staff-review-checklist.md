# Staff 工程师审查清单

> review Skill 的 references/ 目录文件

## 维度一：逻辑正确性 🔍

- [ ] 边界条件是否处理（空数组、null、undefined）
- [ ] 递归是否有终止条件
- [ ] 状态更新是否不可变（React 要求）
- [ ] 并发操作是否安全（快速连续操作）
- [ ] 错误路径是否有处理（try-catch、错误边界）

## 维度二：React 特定 ⚛️

- [ ] 是否有不必要的 re-render（memo/useMemo/useCallback）
- [ ] useEffect 依赖数组是否完整正确
- [ ] key 属性是否稳定唯一（非 index）
- [ ] Context 更新是否导致大面积重渲染
- [ ] ref 是否正确清理（useEffect cleanup）

## 维度三：性能 ⚡

- [ ] 组件树递归遍历的复杂度
- [ ] 是否有 O(n²) 或更差的算法
- [ ] 大列表是否需要虚拟化
- [ ] 是否有潜在的内存泄漏（事件监听器、定时器）
- [ ] 不必要的计算是否用 useMemo 缓存

## 维度四：类型安全 🛡️

- [ ] `any` 类型是否需要收窄
- [ ] ComponentProps 的 `[key: string]: any` 是否过于宽松
- [ ] 类型断言 `as` 是否安全
- [ ] 泛型使用是否合理
- [ ] 可能为 undefined 的值是否处理

## 维度五：可维护性 🔧

- [ ] 命名是否自解释
- [ ] 是否有重复逻辑可抽取
- [ ] 魔法值是否提取为常量
- [ ] 函数是否在 50 行以内
- [ ] 文件是否在 500 行以内

## 维度六：安全性 🔒

- [ ] 用户输入是否转义（XSS）
- [ ] dangerouslySetInnerHTML 是否必要
- [ ] 导出的 HTML 是否安全
- [ ] 是否有硬编码的密钥/凭据
- [ ] 第三方依赖是否已知漏洞

## 严重等级定义

| 等级 | 含义 | 处理要求 |
|------|------|---------|
| 🔴 P0 | 必须修，影响正确性/安全性 | 阻塞合并 |
| 🟡 P1 | 建议修，影响可维护性/性能 | 可后续修 |
| 🟢 P2 | 可选，代码品味/风格 | 不阻塞 |

## 变更大小规范

- 理想：≤100 行变更/PR
- 可接受：100-300 行
- 需拆分：>300 行
