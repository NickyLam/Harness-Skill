# GHBANK 系统设计说明书生成器

> **所属 Capsule**: writing-plans
> **生成器类型**: 过程文档生成器 (Process Document Generator)
> **输入来源**: spec 阶段设计文档 + plan 阶段架构分析 + 技术栈配置
> **输出格式**: Markdown (.md)
> **模板依据**: `doc_template/GHBANK_信息科技部_XX项目_系统设计说明书V3.1.md`

## 生成器职责

将 spec 阶段的设计文档和 plan 阶段的架构分析整合为**符合 GHBANK 规范的系统设计说明书**。

**核心原则：输出模板以原始模板为基础，保留示例值作为格式参照，逐项替换为项目实际值。**

## 原始模板章节清单（必须逐章对齐）

| 序号 | 一级章节 | 二级/三级子章节 | 原始模板关键特征 |
|------|---------|----------------|-----------------|
| 1 | 文档信息 | — | 7 行表格 |
| 2 | 引言 | 2.1~2.4（目的/背景/定义/参考） | 与需求规格说明书结构一致 |
| 3 | 系统架构设计 | 3.1 总体架构(ASCII图) + 3.2 技术架构(5行表格) | 架构图含具体组件名；技术表含选型+说明 |
| 4 | 功能模块设计 | 4.1 模块划分(4列表格) + 4.2 详细设计(类设计代码) | 划分表含依赖列；详细设计含代码块 |
| 5 | 数据库设计 | 5.1 实体关系图(ASCII) + 5.2 数据表(6列表格) | 表含字段名/类型/长度/是否为空/默认值/说明 |
| 6 | 接口设计 | 6.1 规范(文本) + 6.2 接口列表(5列表格) | 列表含地址/方式/功能/请求参数/响应参数 |
| 7 | 安全设计 | 7.1 认证授权 + 7.2 数据安全(列表) + 7.3 防护措施(表格) | 防护措施表 2 列 |
| 8 | 性能设计 | 8.1 指标(2列表格) + 8.2 策略(列表) | 指标表无"说明"列 |
| 9 | 部署架构 | 9.1 服务器规划(4列表格) + 9.2 网络架构(ASCII图) | 规划表含配置/数量/用途 |
| 10 | 附录 | 10.1 术语表 + 10.2 参考资料 + 变更记录 | 术语表 2 列 |

## 填充规则

### 规则 1：严格对齐原始模板格式

输出文档的以下要素必须与原始模板完全一致：
- 一级章节编号 1~10 及其标题名称
- 二级/三级子章节编号和层级深度
- 每个表格的列数、列名、对齐方式
- ASCII 架构图的框线结构和嵌套层次
- 代码块的语法高亮语言标签

### 规则 2：示例值替换而非删除

原始模板中的示例值（如 Web界面、用户服务、t_user、JWT 等）的作用是**展示格式参照**。生成时：

1. 先理解该位置需要什么类型的内容
2. 用项目的实际值替换示例值
3. 如果某位置确实无对应内容，填写合理的默认值并标注原因
4. **禁止留空或仅保留占位符**

### 规则 3：无数据时的兜底值表

| 字段类别 | 兜底值 | 说明 |
|----------|--------|------|
| 审核人/批准人 | "待指定" | 审批流程尚未完成时 |
| 负责人 | "TBD" | 团队分工未确定时 |
| 前端技术栈 | 从 .harness/config.yaml 读取 | 必须有实际值 |
| 后端技术栈 | 从 .harness/config.yaml 读取 | 必须有实际值 |
| 数据库 | 从 .harness/config.yaml 读取 | 必须有实际值 |
| 接口协议 | "HTTP/HTTPS" | Web 应用默认值 |
| 数据格式 | "JSON" | RESTful API 默认值 |
| 字符编码 | "UTF-8" | 国际化默认值 |
| 认证方式 | "JWT Token" 或 "Session" | 根据项目选择 |
| 负载均衡技术 | "Nginx" | 常见选择 |
| 页面响应时间 | "< 3秒"（内部管理）/"< 1秒"（对外） | 根据场景选择 |
| API响应时间 | "< 500ms" | 一般标准 |
| 并发用户数 | "> 100"（内部）/ "> 500"（对外） | 根据场景选择 |
| 系统可用性 | "> 99.9%" | 一般标准 |

### 规则 4：从 spec 需求分析规格说明书继承的字段

以下字段应直接从同项目的 GHBANK 需求分析规格说明书继承，确保两份文档的一致性：

| 继承字段 | 需求规格说明书来源 | 系统设计说明书目标 |
|----------|-------------------|-------------------|
| 项目名称 | 1. 文档信息 - 文档名称 | 1. 文档信息 + 标题 |
| 项目提出者/开发者/用户单位 | 2.2 项目背景 | 2.2 项目背景 |
| 术语定义 | 2.3 定义 | 2.3 定义 |
| 功能模块名称 | 4.1 功能需求各子节 | 4.1 模块划分 + 4.2 详细设计 |
| 性能指标 | 4.2 性能需求 | 8.1 性能指标 |
| 安全需求 | 4.4 安全性需求 | 7. 安全设计 |
| 数据字典 | 6.3 数据字典 | 5.2 数据表设计 |
| 硬件/软件环境 | 5.1/5.2 | 9.1 服务器规划（扩展） |

### 规则 5：禁止残留占位符

最终输出文档中不允许出现：
- `{{...}}` 双花括号
- `[...]` 未替换方括号
- `{variable_name}` 未替换单花括号
- `TBD` / `TODO` / `待补充` / `XXX`
- 原模板的示例值未被替换（如仍出现"用户管理模块"、"t_user"、"订单服务"等非本项目内容）
