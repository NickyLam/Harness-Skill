# Memory Management Schema — 记忆管理规范

> **层级**: L5 治理层支撑
> **设计模式**: Append-Only + Stage Distill（追加写入 + 阶段蒸馏）
> **灵感来源**: Claude Code KAIROS 模式的 append-only 日志 + /dream 蒸馏

## 核心原则

1. **追加优先** — 运行时只追加日志，不更新索引，零决策负担
2. **阶段蒸馏** — 每个阶段完成时提炼日志为结构化记忆，而非等 30 天
3. **检索优先** — 遇到同类任务先查 memory，不重复踩坑
4. **溯源链接** — 每条摘要结论必须可追溯到原始日志

## 目录结构

```
.harness/memory/
├── MEMORY.md              # 长期项目记忆（curated，阶段蒸馏产出）
├── logs/
│   └── YYYY-MM-DD.md      # 每日工作日志（append-only，运行时写入）
└── archive/               # 已蒸馏的旧日志归档
```

## 运行时写入规范（Append-Only）

任务完成时**只追加**到当日日志，**不更新 MEMORY.md**：

```markdown
### HH:MM — {任务简述}

**执行**: {做了什么}
**结果**: ✅ 成功 / ❌ 失败 / ⚠️ 部分成功
**关键决策**: {为什么选这个方案}
**踩坑**: {遇到的问题和解决方法}
**经验**: {下次遇到同样情况该怎么做}
```

**关键约束**：
- 运行时**禁止**更新 MEMORY.md（避免并行子代理写入冲突）
- 运行时**禁止**删除或修改已有日志条目
- 多个子代理可以安全地并发追加到同一日志文件

## 蒸馏触发机制

| 触发时机 | 执行者 | 说明 |
|---------|--------|------|
| 阶段完成（Gate PASS） | 当前 Agent / Team Lead | 最主要的蒸馏时机 |
| 下次会话启动时 | 启动 Agent | 检查未蒸馏日志，补执行蒸馏 |
| 用户手动触发 | 任意 Agent | `/harness memory-distill` |

### 阶段蒸馏流程

```
Stage 完成（Gate PASS）
    │
    ├── 1. 读取本阶段产生的日志条目
    ├── 2. 按主题分组（技术决策 / 踩坑 / 约定 / 偏好）
    ├── 3. 将具体事件提炼为通用规则
    ├── 4. 写入/更新 MEMORY.md
    └── 5. 将已蒸馏的日志条目标记为 ✅ 已提炼
```

### 会话启动蒸馏流程

```
会话启动
    │
    ├── 1. 读取 MEMORY.md → 了解项目全貌
    ├── 2. 读取最近 2 天的日志 → 了解近期上下文
    ├── 3. 检查是否有未蒸馏的日志条目（无 ✅ 标记）
    ├── 4. 如果有 → 执行蒸馏，更新 MEMORY.md
    └── 5. 开始执行用户任务
```

## MEMORY.md 更新规则

MEMORY.md 只在蒸馏时更新，不在运行时更新：

| 触发条件 | 更新内容 | 示例 |
|---------|---------|------|
| 技术决策 | 决策及理由 | "选用 Vitest: Vite 原生支持" |
| 踩坑经验 | 问题和方案 | "react-dnd drop 用 dispatch" |
| 项目约定 | 团队规范 | "Hook 测试放 src/__tests__/hooks/" |
| 用户偏好 | 使用习惯 | "用户偏好中文输出" |
| Skill 效果 | 命中率统计 | "TDD命中率100%" |

**禁止写入**:
- ❌ 临时文件路径
- ❌ 中间搜索结果
- ❌ 工具错误信息（除非有解决方案）
- ❌ 敏感信息（密码/密钥/token）
- ❌ 未经确认的事实

## 检索流程

Agent 开始任何任务前:

```
1. 读取 .harness/memory/MEMORY.md     → 了解项目全貌
2. 读取最近 2 天的日志                 → 了解近期上下文
3. 搜索相关 Capsule/SKILL            → 获取执行指南
4. 执行任务
5. 将新经验追加到当日日志              → 运行时不更新 MEMORY.md
```

## 蒸馏质量检查

- [ ] 每条摘要规则是否有溯源链接？
- [ ] 是否有重复或矛盾的记忆？
- [ ] 已蒸馏的日志条目是否标记了 ✅？
- [ ] 敏感信息是否已清理？

## 与其他组件的协作

| 组件 | 协作方式 |
|------|---------|
| governance | governance 定义"何时沉淀"，memory 定义"怎么写" |
| orchestrator | 角色切换时读 memory 获取上下文 |
| systematic-debugging | 调试前先查 memory 中的 bug patterns |
| gating | Gate 失败的原因追加到日志，蒸馏时提炼到 MEMORY.md |
| wave-executor | 子代理并行执行时只追加日志，避免 MEMORY.md 写入冲突 |
